# Pi

`./default.nix` and `../codex.nix` both use `../AGENTS.md` as their global
instructions. Edit that shared file to update both agents.

Pi uses the native Home Manager module, `pi-vim`, and pinned npm extensions.
CPA (`gpt-6.1-sol`, medium reasoning) is the default provider; select another
with `/model`. Saved authentication, sessions, and extension state stay local.

`settings.json`, `models.json`, `web-search.json`, and `auth.json` are writable.
Activation merges the declared defaults into the first three, preserving
unrelated settings and saving the original once as `*.pre-hm` (mode 0600).
Malformed JSON and symlinked targets are rejected rather than overwritten. Do
not activate while Pi is writing settings. `mcp.json` and the subagent presets
are HM-managed.

## Models

| Model | CPA context |
| --- | ---: |
| `gpt-6.1-sol`, `gpt-6.1-terra` | 872,000 |
| `gpt-6-sol`, `gpt-5.6-sol`, `gpt-5.5` | 272,000 |

The 872,000-token windows are a requested working budget, not a verified
endpoint maximum; Pi's compaction policy still reserves room within them.
Activation also sets the OpenAI API `gpt-6.1-sol` window to 500,000 and
registers `gpt-6.1-terra` for the `openai` and `openai-codex` providers
(272,000 context, 128,000 output). Other local model metadata is preserved.

## Subagent presets

Presets are generated by `_subagents.nix` from `agents/`; edit those sources,
not the generated files in `~/.pi/agent/agents/`.

Use `implementer-fast-*` (`gpt-6-luna`) for well-scoped changes with a clear
approach, and `implementer-hard-*` (`gpt-6.1-terra`) for difficult debugging,
ambiguous interactions, or correctness-sensitive work. Escalate from fast when
complexity emerges; both tiers share the same contract and high reasoning.

## Retries

Transient failures retry up to 20 times with exponential backoff from 5 to 60
seconds, roughly 17 minutes in total. Permanent errors are not retried.

## Credentials

SOPS secrets are exposed as native Pi `!command`s that read the decrypted file
at use time. Only the command and secret path enter the Nix store, and rotation
is visible without exporting variables. Missing or unreadable secret files fail
at credential use, not at startup. Saved `/login` credentials take precedence
and are never modified; OAuth does not fall back to a configured key. Add
entries with `sops secrets/secrets.yaml`. CPA accepts only allowlisted command
names, so its command uses `cat` from `PATH`; the other consumers use an
absolute path.

| Secret | Used for |
| --- | --- |
| `pi-cpa-api-key` | CPA API key, also in the rendered provider config |
| `internal-cpa-url` | CPA endpoint, rendered at runtime, not in the store |
| `deepseek-api-key` | `models.json` provider `deepseek` |
| `opencode-api-key` | built-in `opencode-go` provider |
| `context7-api-key` | Context7 MCP header |
| `exa-api-key` | `web-search.json` `exaApiKey` |

Set `programs.pi-coding-agent.cpaApiKeySecret = null` to omit the CPA command
and use `CLIPROXYAPI_API_KEY` or `/login cpa` instead. Activation adds
`198.18.0.0/15` to `web-search.json` `ssrf.allowRanges` for the local fake-IP
proxy. The bundled Exa CLI/MCP must select the same config directory as Pi
(`PI_CODING_AGENT_DIR` or XDG config). Context7 is declared in the HM-managed
`mcp.json`; change it there rather than with `pi mcp add`, and check it with
`pi mcp list`.

## Extensions and updates

Extension definitions live in `extensions/_pins.nix`; `package.json` is generated
from it at build time and is not committed. `package-lock.json` holds the
resolved tree and is committed. After changing a pin or adding an extension, run
`just lock-pi-extensions` to sync the lock; `just update-pi-extensions` refreshes
floating versions. `just update` also refreshes `flake.lock`. Both use the
pinned npm from the `pi-extensions` dev shell. `pi update` does not update this
Nix-managed bundle.
