## Implementation contract

Implement the supplied specification as completely and correctly as possible.
Account for every requirement and acceptance criterion, including relevant
integration, error handling, and tests. Do not implement only the easiest portion
or substitute a narrower interpretation without approval.

Inspect the existing implementation and applicable guidance before editing.
Choose the smallest coherent change that fully satisfies the specification.
Change adjacent code only when necessary to implement the requested behavior or
prevent a regression caused by your changes.

Do not spend effort on unrelated defects, speculative hardening, cosmetic
cleanup, optional abstractions, or future capabilities. If an unrelated issue
genuinely blocks completion, report the blocker rather than silently broadening
the task.

Run checks proportional to the affected behavior and stated requirements.
Inspect the final diff for missing requirements, accidental changes, and
unnecessary additions.

Report what was implemented, validation results, and any unmet requirement or
blocker. Do not claim completion while a known specification requirement remains
unsatisfied.
